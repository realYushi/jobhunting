# Job Hunting

Automated job discovery and application-package system powered by Claude Code.

## What It Does

The repo supports two workflows:

1. **One-off application package** — given a job description, research the role,
   generate a tailored resume, write a cover letter, render PDFs, and update the
   application tracker.
2. **Job research pipeline** — scrape job boards, score listings against the
   candidate profile, package the best matches, and queue them in
   `applications/INBOX.md` for review.

`templates/base-resume.json` is the single source of truth for the candidate
record. `LinkedIn-CV-Profile.md` is a one-way mirror generated by the
`linkedin` skill — useful for keyword search and cover-letter context, never
hand-edited.

## Quick Start

For a single job, paste the job description into Claude Code and say:

> apply for this job

If the `job-applier` skill is installed, it runs the full package workflow.

For job discovery, say:

> run job research

The `job-research` skill runs the orchestrated scrape → score → package flow.

## Job Research Pipeline

Supported scraper sources:

- LinkedIn
- Seek
- Hiring.cafe
- Working Nomads
- Wellfound
- We Work Remotely

Default sources are configured in `tools/search-config.json`. Current default:
`wellfound` and `weworkremotely`.

### Recommended orchestrated flow

```bash
# 1. Scrape listings only
python3 tools/pipeline.py --scrape-only /tmp/jobhunting-listings.json
```

Then ask a Sonnet subagent to read `/tmp/jobhunting-listings.json`, apply
`tools/scoring-rubric.md`, and write `/tmp/jobhunting-scores.json`.

```bash
# 2. Package every listing that passed scoring
python3 tools/pipeline.py --from-scores /tmp/jobhunting-scores.json --cap 100
```

If the package stage reports that cover letters need fill-in, ask a Sonnet
subagent to process `/tmp/jobhunting-cover-queue.json`, then render PDFs:

```bash
python3 tools/cover_letter_pdf.py --queue /tmp/jobhunting-cover-queue.json --force
```

### Smoke-test a single source

```bash
python3 tools/pipeline.py --dry-run --source linkedin --scrape-only /tmp/linkedin.json
python3 tools/pipeline.py --dry-run --source seek --scrape-only /tmp/seek.json
python3 tools/pipeline.py --dry-run --source hiringcafe --scrape-only /tmp/hiringcafe.json
python3 tools/pipeline.py --dry-run --source workingnomads --scrape-only /tmp/workingnomads.json
python3 tools/pipeline.py --dry-run --source wellfound --scrape-only /tmp/wellfound.json
python3 tools/pipeline.py --dry-run --source weworkremotely --scrape-only /tmp/weworkremotely.json
```

Note: scrape-only runs still reconcile `applications/INBOX.md` first and mark
surfaced listings as seen in `applications/application-tracker.json`. Commit or
stash tracker changes before smoke testing if you need a perfectly clean diff.

### Useful flags

```bash
python3 tools/pipeline.py --profile product-engineer --profile ai-native
python3 tools/pipeline.py --source linkedin --source seek
python3 tools/pipeline.py --cutoff 70
python3 tools/pipeline.py --cap 5
python3 tools/pipeline.py --no-fetch-jd
python3 tools/pipeline.py --dry-run
```

## Manual Application Tools

```bash
# Preview a complete local application package without writing files
python3 tools/apply.py --job job.md --company "TechCorp" --position "Frontend Engineer" --role frontend --dry-run

# Create local research/documents folders, resume.json, cover-letter draft, and tracker entry
python3 tools/apply.py --job job.md --company "TechCorp" --position "Frontend Engineer" --role frontend --keywords React TypeScript

# Show tracker status and missing PDFs
python3 tools/status.py

# Generate only a tailored resume (JSON)
python3 tools/resume.py --company "TechCorp" --role frontend

# Push to Reactive Resume server, if configured
python3 tools/reactive_resume.py push --file path/resume.json --name "..." --slug "..." --dry-run

# Clean old archives
./tools/cleanup-archive.sh
```

Requires `typst` on PATH for local PDF rendering:

```bash
brew install typst
```

## Browser Harness Setup

The scrapers use `browser-harness` to control your real Chrome browser through
Chrome DevTools Protocol (CDP). This lets LinkedIn and other sites use your
normal logged-in browser session.

### 1. Install `browser-harness`

Install the CLI if it is not already on PATH:

```bash
npm install -g browser-harness
# or, if you use Bun globally
bun add -g browser-harness
```

Check that the command is available:

```bash
browser-harness --help
```

### 2. Start Chrome with remote debugging

Close any existing Chrome instance, then start Chrome with a CDP port:

```bash
/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome \
  --remote-debugging-port=9222 \
  --user-data-dir="$HOME/.chrome-jobhunting"
```

The separate `--user-data-dir` avoids fighting your normal Chrome process. Log
in to LinkedIn or any other job board inside this Chrome window before running
scrapers that need an authenticated session.

### 3. Verify CDP is reachable

Open this URL in any browser:

```text
http://localhost:9222/json/version
```

You should see a JSON response with Chrome and DevTools metadata.

### 4. Verify `browser-harness` can see tabs

Run a tiny harness command:

```bash
browser-harness <<'PY'
print(list_tabs())
PY
```

If it prints a list of tabs, the pipeline can use the browser.

### 5. Run a scraper smoke test

```bash
python3 tools/pipeline.py --dry-run --source linkedin --scrape-only /tmp/linkedin.json
```

Troubleshooting:

- `browser-harness not found on PATH`: install the CLI or open a shell where the
  global npm/Bun bin directory is on PATH.
- connection refused / no tabs: Chrome is not running with
  `--remote-debugging-port=9222`, or another Chrome instance took over.
- LinkedIn returns empty or login content: open LinkedIn in the remote-debugging
  Chrome window and log in manually first.
