# Truthfulness Validation Checklist

**Purpose**: Prevent fabrication of experience, projects, or achievements in application materials

## CRITICAL: Verify Against Source Materials

### Primary Sources for Verification
- `templates/resumes/base-resume.json` - Complete work history, education, skills
- GitHub repositories - Actual project work and technologies used
- LinkedIn profile - Professional experience validation
- Academic transcripts - GPA and educational achievements

## Verification Categories

### 1. Work Experience Claims ✅/❌
**Check ALL mentions of**:
- [ ] Company names and positions held
- [ ] Employment dates and duration
- [ ] Specific responsibilities and achievements
- [ ] Technologies used in professional settings
- [ ] Team sizes, reporting relationships
- [ ] Performance metrics and improvements

**Common Fabrications to Watch For**:
- Adding responsibilities that weren't actually performed
- Inflating team leadership roles
- Claiming technologies not actually used professionally
- Exaggerating project scope or impact

### 2. Project Experience Claims ✅/❌
**Verify ALL mentions of**:
- [ ] Personal project names and descriptions
- [ ] Technologies and frameworks used
- [ ] Project outcomes and metrics
- [ ] GitHub repository existence and activity
- [ ] Deployment status and performance claims
- [ ] Learning objectives and achievements

**Red Flags**:
- Projects not found in GitHub/portfolio
- Technology stacks not evidenced in code
- Performance metrics without basis
- Claiming "production" status for personal projects

### 3. Educational Claims ✅/❌
**Confirm ALL details**:
- [ ] Institution names and degrees
- [ ] GPA and academic standing
- [ ] Graduation dates or expected completion
- [ ] Relevant coursework mentioned
- [ ] Academic projects and achievements
- [ ] Certifications and credentials

**Never Assume**:
- Academic performance beyond what's documented
- Coursework not explicitly listed
- Degrees in progress without confirmation

### 4. Skills and Technical Claims ✅/❌
**Validate ALL mentions of**:
- [ ] Programming languages and proficiency levels
- [ ] Frameworks, libraries, and tools
- [ ] Cloud platforms and services
- [ ] Databases and data technologies
- [ ] Development methodologies
- [ ] Industry-specific knowledge

**Verification Methods**:
- Check code repositories for evidence of use
- Confirm through project implementations
- Validate against resume skills sections
- Ensure consistency across all materials

### 5. Achievement Metrics ✅/❌
**Verify ALL quantified claims**:
- [ ] Performance improvement percentages
- [ ] System uptime and reliability metrics
- [ ] Speed or efficiency improvements
- [ ] Cost savings or business impact
- [ ] User adoption or engagement numbers
- [ ] Academic grades and rankings

**Documentation Required**:
- Source of measurement for each metric
- Context and timeframe for achievements
- Methodology for calculating improvements
- Baseline and comparison points

## Validation Process

### Step 1: Extract All Claims
List every factual claim in the document:
- Work experience details
- Project descriptions and outcomes  
- Academic achievements
- Technical skills mentioned
- Quantified metrics and improvements

### Step 2: Cross-Reference Sources
For each claim, check against:
- Resume sections (work, education, skills, projects)
- GitHub repositories and commit history
- Portfolio websites and documentation
- LinkedIn profile information

### Step 3: Flag Discrepancies
Mark any claims that:
- Cannot be verified against sources
- Contradict documented information
- Represent assumptions or extrapolations
- Appear to be fabricated or exaggerated

### Step 4: Correction Protocol
If false claims found:
1. **IMMEDIATE STOP** - Do not proceed with quality check
2. **Document all false claims** with specific details
3. **Restart with truthful foundation** using only verified information
4. **Review agent processes** to prevent future fabrication

## Quality Assurance Standards

### Acceptable Positioning
- ✅ Connecting transferable skills to new domains
- ✅ Expressing genuine interest in learning
- ✅ Highlighting relevant aspects of actual experience
- ✅ Drawing parallels between real projects and job requirements

### Unacceptable Fabrication
- ❌ Claiming projects or experience that don't exist
- ❌ Inventing metrics or achievements
- ❌ Stating skills or knowledge not actually possessed
- ❌ Exaggerating scope or impact of real work

## Agent Instructions

### For Company Research Agents
- Research company thoroughly BUT do not invent candidate connections
- Suggest positioning strategies based on ACTUAL candidate background
- Recommend learning interests, not fictional experience

### For Document Creation Agents
- Use only verified information from candidate sources
- Frame real experience in compelling but truthful ways
- Express genuine interest in growth without claiming false expertise
- Position transferable skills honestly

### For Quality Check Agents
- Truthfulness validation MUST be first step
- Reject any materials containing false claims
- Require restart with accurate information
- Document validation process and sources checked

---

**Remember**: Credibility is built on truth. One false claim can destroy trust and end candidacy immediately.
