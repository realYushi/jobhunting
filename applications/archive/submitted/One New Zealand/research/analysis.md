# Job Analysis: One New Zealand - Frontend Engineer - Digital

## 1. Role Overview

- **Position Level**: Mid-level frontend/product engineering role, with a notable Flutter-first requirement.

- **Core Mission**: Build and maintain web and mobile applications that improve customer and employee digital experiences, integrate reliably with backend APIs, and support One NZ's ambition to become a highly AI-enabled telco.

### Human Adjacency Notes

The tool is literal and misses several adjacent matches:

- **AI-assisted tools**: Strong verified match through AI agents, OpenAI Agent SDK, AI-assisted review workflows, and Azure AI certification.
- **Web/mobile applications**: Web application experience is verified; mobile/Flutter is the real gap.
- **RESTful/API integration**: API-backed full-stack work is verified, though REST/GraphQL are not named directly in the profile.
- **Performance optimisation**: The Truss House project includes a lazy-loaded chatbot widget built to avoid initial page-load impact.
- **Testing**: The Decoded role includes a QA/testing layer for generated work, but not explicit unit/integration test frameworks.

### Readiness Level

Proceed with a transparent application. The strongest case is not "I already do Flutter"; it is "I build production-facing web products, integrate APIs, use AI-assisted engineering tools responsibly, and can ramp into Flutter from a solid frontend foundation."

## 4. Application Strategy

### Top Selling Points

1. **Frontend/product delivery**: React, TypeScript, Next.js, Vue, Astro and Tailwind experience across internal tools and client-facing applications.
2. **API and full-stack fluency**: Current and project work spans frontend/back-end architecture, Node.js, .NET, Azure, and CI/CD.
3. **AI-enabled SDLC alignment**: One NZ explicitly wants AI-assisted tooling; candidate has verified experience building AI agents, coding-agent workflows, and human-in-the-loop review systems.
4. **Local fit**: Auckland-based NZ Permanent Resident, no sponsorship required.

### Positioning Gaps

- **Flutter / React Native**: Do not claim experience. Position as a framework ramp-up from a strong React/TypeScript and product-engineering base.
- **GraphQL / ADO**: Do not claim experience. Emphasise API integration, Git, GitHub Actions, and ability to work with team standards.
- **Accessibility**: Mention responsive, user-facing frontend work only if kept general; avoid claiming formal accessibility expertise.

### Strategic Keywords

- **High-Priority**: React, TypeScript, API integration, Git, CI/CD, AI-assisted tools, frontend, web applications.
- **Use carefully / only in context of gaps**: Flutter, GraphQL, React Native, ADO.

### Cover Letter Focus

1. Connect to One NZ's purpose of a better-connected Aotearoa and its ambition to become highly AI-enabled.
2. Lead with current GrowLab work building internal tools, client applications, and AI workflows.
3. Cite concrete evidence: Truss House site/chatbot, React/TypeScript + .NET task manager with GitHub Actions CI/CD, Decoded coding-agent platform.
4. Be transparent about bringing React/web and AI-assisted delivery strengths into a Flutter-first team.

## 5. Red Flags & Concerns

- The JD is Flutter-first; the candidate profile does not support Flutter.
- No salary range is listed.
- Some requested terms are not verified: React Native, GraphQL, ADO, formal accessibility expertise.
- Application should be submitted only if the user is comfortable applying as an adjacent-match candidate rather than a direct Flutter specialist.
